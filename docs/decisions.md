### D-01. 백엔드는 Hono(TypeScript)를 유지한다

- **이유:** 이미 Swagger UI(`/api/swagger`)와 Scalar(`/api/docs`)가 zod 스키마에서 나온다. 프론트와 백엔드가 `packages/contracts`의 같은 스키마를 import하므로 요청 검증, API 문서, 프론트 타입이 한 곳에서 나온다. 언어가 TypeScript 하나라 3명이 서로의 코드를 읽을 수 있다.
- **대안:** FastAPI. Swagger는 기본 제공이지만 Python과 TS 두 언어가 생기고, 프론트 타입을 OpenAPI에서 따로 생성해야 하며, 스캐폴드·CI·배포를 다시 만들어야 한다.
- **다시 볼 조건:** 백엔드를 Python 라이브러리 없이는 만들 수 없는 기능이 생길 때.

### D-02. API와 DB는 EC2 한 대에서 docker compose로 돌린다

- **이유:** 로컬(`infra/compose.yaml`)과 같은 모양이라 이해하기 쉽다. 카카오 로그인과 웹 푸시에 필요한 외부 통신이 추가 비용 없이 된다. 프리 티어 크기(t3.micro) 한 대로 dev와 prod를 함께 돌릴 수 있다.
- **대안:** Lambda + RDS. RDS에 비공개로 붙으려면 Lambda가 VPC 안에 있어야 하고, 그러면 외부 통신에 NAT가 필요해 월 수십 달러가 든다. RDS를 공개로 열면 보안이 약해진다.
- **다시 볼 조건:** 파일럿 이후 실제 사용자가 늘어 가용성(서버 한 대가 멈춰도 계속 동작)이 필요할 때.

### D-03. 웹은 Amplify 앱 두 개, `/api`는 같은 출처 프록시

- **이유:** PR마다 미리 보기 주소가 자동으로 생겨 팀원이 서로의 화면을 바로 본다. 웹과 API가 같은 출처라 로그인 쿠키가 iOS Safari에서 제3자 쿠키로 막히지 않고 CORS가 필요 없다. Amplify의 재작성 규칙은 앱 단위라서 dev와 prod를 앱 두 개로 나눈다.
- **대안:** S3 + CloudFront. 비용은 더 적지만 PR 미리 보기를 직접 만들어야 한다.
- **다시 볼 조건:** 도메인을 확보해 웹과 API를 한 CloudFront 아래로 합칠 때.

### D-04. 사람은 Identity Center, 배포는 GitHub OIDC

- **이유:** 오래 가는 액세스 키가 어디에도 생기지 않는다. 팀원은 SSO로 짧은 자격증명을 받고, GitHub Actions는 이 저장소의 `main`·`release`에서만 역할을 받는다. 팀원 권한은 보기와 접속으로 제한하고 인프라 변경은 관리자만 한다.
- **대안:** IAM 사용자 3명 + 액세스 키. 키가 유출되면 계정 전체가 위험해진다. Identity Center를 쓸 수 없으면 콘솔 비밀번호 + MFA + `aws login`으로 대신한다([aws-setup.md](aws-setup.md) 3-B).

### D-05. DB 도구는 Drizzle ORM + drizzle-kit

- **이유:** 스키마를 TypeScript로 쓰고, SQL 마이그레이션 파일을 만들어 PR에서 검토할 수 있다. 런타임이 가볍다. 규칙은 [database.md](database.md).
- **대안:** Prisma(엔진이 무겁고 배포 이미지가 커짐), Kysely(쿼리는 좋지만 마이그레이션을 따로 골라야 함).

### D-06. react-router + TanStack Query

- **이유:** 화면이 많고(LF-01~LF-20), 로딩·오류·재시도 상태를 화면마다 같은 방식으로 다뤄야 한다. 규칙은 [frontend.md](frontend.md).

### D-07. 애니메이션은 SEED 토큰과 CSS

- **이유:** SEED 컴포넌트가 시트·다이얼로그 움직임을 이미 갖고 있고, 시간·곡선 토큰(`--seed-duration-*`, `--seed-timing-function-*`)이 있다. 라이브러리를 추가하면 번들이 커지고 사람마다 다른 움직임이 생긴다. 규칙은 [interaction.md](interaction.md).
- **다시 볼 조건:** 끌어서 닫기처럼 CSS로 어려운 제스처가 필요할 때.

### D-08. 안내는 제목·본문·사진만

- **이유:** 집주인이 붙여넣은 카톡 문구를 그대로 보여줘야 하고, 입력하지 않은 요일표 같은 구조가 조회 화면에 자동으로 나타나면 안 된다. 상세·첫날 카드·미리 보기가 같은 값을 쓴다. 근거는 [lofi/screens.md](../lofi/screens.md) 데이터 귀속.

### D-09. 팁·메모 작성자는 내부 저장, 다른 거주자에게 비공개

- **이유:** 본인 글 수정·삭제와 신고 처리를 하려면 작성자를 알아야 한다. 다른 거주자에게는 보이지 않는 것만 약속한다. 근거는 [lofi/screens.md](../lofi/screens.md) 작성자 정책.
